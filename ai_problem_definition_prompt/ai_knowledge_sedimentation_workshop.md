# Part A — 課程核心

---

## 1. 課程核心理念

上一代的 AI 課在教怎麼把話講清楚。那個問題，模型自己解決了。

我們在 2026 年跑過一次實測，數據附在教材裡。三個人用三個隨便打的提問，跑同一份會議逐字稿，三份產出都有負責人、都有期限、都排得整整齊齊。連「總結一下這場會議」都給了七項待辦。

但三份的待辦數量是 9、8、7，而且最重要的那項交付有兩份漏掉了。三份都把「請人去評估的方案」寫成了「決議」。

AI 沒做錯什麼。它只是每一次都替你做了一堆決定，而那些決定本來應該是你的。

Claude Code 創造者 Boris Cherny 在 Opus 5 上線時，砍掉了自家 system prompt 的 80% 以上，模型表現反而更好。他的建議是每六個月刪掉你的 CLAUDE.md、skills、hooks，只在看到模型重複跌倒的地方才加回來。

而他的第一守則是這句：

> 「給它一個驗證自己成果的方法，品質會變 2 到 3 倍。」
> 「驗證，大概是大家最沒做對的那一件事。」

所以這門課的核心主張只有一句話可以概括：

```
會被模型升級淘汰的：  指示（怎麼做）      ← Boris 砍掉的那 80%
留得住的：            驗證（怎麼算做好）  ← 他說這是第一名沒做對的事
```

**目標**：學員在兩個半天結束時，擁有一個自己領域的、驗證過的、別人也能用的 skill 資產，並具備三項不會過期的能力——判斷模型會在哪裡壞掉、把腦中的品味寫成可核對的規格、用消融測試決定哪些規則該留該刪。

## 2. 核心框架

### 主框架：三問

所有提示詞框架（STRIKE、CTCO、CO-STAR）拆開來都在問同樣三件事：

| # | 問題 | 現在的模型 | 誰負責 |
|---|------|-----------|--------|
| ① | 我要什麼？ | 你講得零零落落它也接得住 | AI 幫你補 |
| ② | 我給你什麼？ | 貼上去就好 | AI 幫你讀 |
| ③ | 怎麼算做好了？ | 它永遠猜不到 | 只有你 |

STRIKE 在課程中的位置：第一天教，15 分鐘，當作初學者的鷹架，然後當場證明它的天花板。

| STRIKE | 折進三問的哪一格 |
|--------|-----------------|
| S 情境、T 任務、R 角色 | ① 我要什麼 |
| I 輸入 | ② 我給你什麼 |
| K 驗收 | ③ 怎麼算做好了（只有一格） |
| E 範例 | ③ 的補強 |

這幾個框架都很會教①②，第③格一律最弱，而那格是模型唯一補不上的。

框架最弱的那一格，就是你最貴的資產。

### 次框架：沉澱階梯 L0 到 L4

| 層 | 形態 | 什麼時候往上爬 | 成本 |
|---|------|--------------|------|
| L0 | 每次重打 | | 每次都痛 |
| L1 | 存一段話 | 打第二次 | 1 分鐘 |
| L2 | 挖空的填空卡 | 第三次，發現有些地方每次在換 | 15 分鐘 |
| L3 | 一個資料夾（加驗收、加範例） | 發現「光有話不夠，還要附那份檔」 | 1–2 小時 |
| L4 | 自動觸發 | 你已經懶得想起來要用它 | 看工具 |

爬的規則很單純：用不順的那一格，就是下一格要補的東西。本課做到 L3。

### 第三框架：消融測試（Boris 法）

決定一條規則該不該留的唯一方法：

```
① 全部刪掉
② 跑同一份考卷 → 記分
③ 一塊一塊加回來，每加一次跑一次
④ 只留下真的讓分數上升的
```

加回來的判準：只有當你看到它重複在同一個地方跌倒。

## 3. 目標受眾 (ICP)

### 主要族群

PM、行銷、企劃、分析、顧問這類知識工作者，有大量重複性的判斷工作，每次都要重新交代 AI。

小主管與團隊 leader，需要把自己的品質標準傳給團隊，但講不清楚。

已經在用 AI 但卡住的人，用得很順，但累積不出東西。

### 次要族群

企業 L&D 或數位轉型負責人，要導入 AI 但缺可驗證的成效指標。

行政與人資，高頻文書，最適合沉澱。

### 學員畫像

每天用 AI，但沒有任何東西是可以重複使用的。有過「上次明明弄得很好，這次又要重來」的挫折。零技術背景，會打字、會複製貼上就能上手。對「這東西半年後還能不能用」有疑慮——Block D 專門回答這個。

### 不適合的人

從沒用過 AI 對話工具的（建議先上基礎操作課）。工作內容完全不重複、每次都是全新任務的。想要拿 100 個現成模板走的（本課不發模板，教你長出自己的）。

### 前置條件

- 筆記型電腦
- 穩定網路
- 至少一個通用 AI 對話工具帳號（免費版即可）
- Day 2 前：帶著 Day 1 之後實際用過 2–3 次的對話紀錄

## 4. 課程大綱（8 小時，兩個半天）

為什麼是兩個半天？因為本課的核心心法是「第三次才沉澱」。一天課只能做到「第一次寫下來」，做不到「寫下來、拿去用、發現漏了、補回來」。中間那一週不是休息，是課程的一部分。

---

## Day 1 — 懂機器、會對話（09:00 – 13:00）

### 開場（09:00 – 09:20）

今天不背口訣。今天先搞懂你手上這台機器是什麼。

展示終點：直接打開一份做好的 skill 資料夾，讓學員先看到兩週後要做出什麼。接著說明兩段式結構與中間那一週的作業。

---

### Block A（09:20 – 11:00）認識這台機器

你不知道它怎麼壞的，就永遠只能當乘客。

主題是用五個對比實驗，親手建立對模型的物理直覺。目標是學員能說出「產出是抽出來的不是查出來的」、能自己估一次任務的成本、能指出模型會在哪裡崩。

**實驗一：同一題問三次（15 min）**
三個不同的答案，說明產出是抽樣不是查表。為什麼「上次明明可以」不是你的錯覺，也不是你的錯。

**實驗二：不給資料對給資料（20 min）**
這個感官最強。問一件它不可能知道的事，例如公司內規或內部代號，它會一本正經地編給你看。幻覺不是 bug，是它在完成你交付的任務。加上資料再問一次，看落差。由此引出：要求它先列引用再作答。

**實驗三：思考深度是一個旋鈕（20 min）**
同一題，低 effort 對高 effort。原來「聰明」是可以調的，而且要付錢。哪些任務值得付，哪些不值得。

**實驗四：三家工具跑同一題（20 min）**
通用對話工具的個性差異：長度、語氣、結構偏好、拒答邊界。要問的是哪一家適合你這個任務，強弱排名反而次要。順帶教怎麼用自己的題目，五分鐘測出該用哪一家。

**成本素養：算一次你剛剛的帳（25 min）**
token 是什麼、為什麼中文比英文貴。把上面四個實驗的用量估出來。降本的三個槓桿：選對層級、不塞廢話、快取重複的部分。

實作活動：每人用自己工作上的一個真實問題跑完五個實驗，填「模型體感表」。

---

### Block B（11:10 – 12:50）提示詞作為設計

提示詞仍然是設計。但它設計的是「你要什麼」，不是「你怎麼說」。

目標是學員能用對話迭代逼近自己要的產出，並且留下一份可以拿來沉澱的對話紀錄。

**STRIKE 快講（15 min）**
六字訣一次講完，當作初學者的抓手。然後立刻用它的產出跑 5 次，還是 5 種結果。收在這句：框架幫你問問題，不幫你回答。它問得了①②，答不了③。

**對比實驗：規格模糊對規格明確，各跑 5 次（25 min）**
這是本課唯一還有效的 before/after 對照。關鍵在於差異不在單次品質，在 5 次的變異度。模糊規格 3/5 可用，明確規格 5/5 可用。

**對話式迭代：把「你要什麼」逼出來（35 min）**
這一段的真正產出不是好 prompt，是一份對話紀錄。

一次問不到很正常，用修正逼近。每一句「不對，再短一點」「把負責人加上去」「不要用這個詞」，都是你的隱性標準當場被逼出來的那一刻。學員針對自己的任務跑一輪完整迭代，存下紀錄。那就是 Day 2 的原料。

**工具地景：三類，分界線是「誰決定下一步」（25 min）**

| 類型 | 誰決定下一步 | 適合 |
|------|------------|------|
| 對話型 | 你，每一步 | 單步、需要你判斷、變異大 |
| 協作型（cowork） | 你劃邊界，它在裡面跑 | 有明確產出物、要來回修 |
| 自主型（E2E agent） | 它自己 | 步驟多、可驗證、錯了成本低 |

判斷原則：你放多少控制權出去，要跟你能容忍多少失控匹配。具體平台名單見附件，每期開課前更新。

實作活動：用自己的真實任務跑完整迭代，存下完整對話紀錄（截圖或匯出）。

**課後作業（課程的一部分）**

這一週，用你今天摸出來的方式，把那件工作實際做 2–3 次。每一次都把對話紀錄存下來。Day 2 就是拿這些來收成。

## Day 2 — 收成資產（一週後，09:00 – 13:00）

### 回收（09:00 – 09:20）

快速盤點這一週做了幾次、哪裡卡。沒做的人啟用公版任務，見風險應對。

---

### Block C（09:20 – 11:20）從對話紀錄收成 skill

你不需要「想出」你的驗收標準。你只需要回頭把自己罵過 AI 的話撿起來。

目標是每位學員產出一個完整的 skill 資料夾，並拿到通過率數字。

**抽修正：對話紀錄是你品味的逐字稿（25 min）**

把每一句「不對，要改成…」畫出來，對應到五類中的哪一類：

| 值得寫下來的五類 | 為什麼模型拿不到 |
|----------------|-----------------|
| ① 驗收標準 | 這是你的品味，不是常識 |
| ② 私有事實 | 不在它的訓練資料裡 |
| ③ 流程順序 | 你的組織才有 |
| ④ 負例 | 資訊量比正例高 |
| ⑤ 參考成品 | 比一百句描述都準 |

這張清單裡沒有「說話技巧」那一格。那就是「不被框架綁住」的具體意思。

**結構化：story 到 user flow 到精煉（30 min）**

```
story        →  這個 skill 什麼時候用（以及什麼時候不用）
user flow    →  步驟：不變的寫死、會變的挖空
結構化       →  用 AI 把對話紀錄轉成檔案骨架
精煉         →  把散在對話裡的修正，收斂成可核對的 yes/no
```

**驗收檢核：把「認得出」變成「說得出」（35 min）**

這是全課最難的動作。唯一規則是每一條都要能用一句 yes/no 回答。

| 不可以 | 要改成 |
|----------|----------|
| 要夠專業 | 沒有出現口語詞 |
| 要夠詳細 | 每個項目都有負責人和日期 |
| 排版清楚 | 一頁以內，用表格不用長段落 |

三個引出技法：對比引出（給兩份問哪份好）、退件倒推（上次被退是因為什麼）、分歧倒推（兩份都對但不一樣的地方）。

**裝起來與跑考卷（30 min）**

資料夾裝進工具，三種裝法見工具矩陣。從這一週的真實案例挑 5 題當考卷。基線用 Day 1 的產出，不用重跑，省時且更誠實。算通過率。

實作活動：產出完整 skill 資料夾與通過率數字。

產出物長這樣：

```
你的任務名稱/
├── SKILL.md          什麼時候用我、步驟、成品照
├── 驗收檢核.md        幾條 yes/no，全過才能交
├── 禁區.md            絕對不能出現的東西
├── 好範例/            你認可的成品
├── 壞範例/            踩過的雷，加上為什麼爛
└── 考卷.md            5–10 題真實案例
```

### Block D（11:30 – 12:40）汰換與消融

這一節專門回答一個問題：我今天花的時間，會不會因為模型變強就白費？

目標是學員能自己判斷一條規則該留該刪，並帶走一份汰換觸發清單。

**兩類規則，命運相反（15 min）**

| 類型 | 例子 | 命運 |
|------|------|------|
| 業務要求 | 金流一律轉人工、不能提競品名、行動項一定要有負責人 | 永久保留 |
| 怕 AI 出錯 | 「請仔細檢查」「不要遺漏」「一步一步思考」 | 模型換代就變雜訊 |

一句話判斷法：如果今天是一個很資深的人類同事來做，我還需要跟他講這句嗎？需要就是業務要求，不需要就是你只是不放心。

**分組消融實驗（35 min）**

這是全課的收束。把 skill 拆成三塊：指示塊（步驟）、驗證塊（檢核加禁區加成品照）、範例塊。

全班分四組，同一份 5 題考卷，條件不同：

| 組 | 條件 | 分數 |
|---|------|------|
| 對照 | 全部都在 | ___ |
| A | 拿掉指示塊 | ___ |
| B | 拿掉驗證塊 | ___ |
| C | 拿掉範例塊 | ___ |

各組上台報分數。

高機率的結果是：拿掉指示，分數幾乎不動；拿掉驗證，分數掉最多。

如果是這樣，全課的結論不是老師講的，是學員自己量出來的：你花時間寫的「怎麼做」，模型不需要；你沒花時間寫的「怎麼算做好」，才是真的在撐分數的東西。

萬一結果不同也沒關係，那也是真資料，教到的是「去測，不要猜」，一樣是主軸。

**汰換觸發清單（10 min）**

Boris 講六個月，但模型改版比這快。改成事件觸發更實用：

```
換模型 / 工具改版 / 連續兩次覺得產出怪怪的  →  跑一次消融
```

日曆到期不會有人記得，事件觸發才會。

**交棒測試（10 min，示範加回家做）**

把 skill 給一個沒做過這件事的人。他回頭問你的每一句話，都是你還沒寫下來的那格判斷。三輪就收斂。

---

### 總結（12:40 – 13:00）

回到第一天那張圖。

早上第一天我說，所有框架都在問三個問題，第三個沒人幫你答。你們兩週做的整個資料夾，成品照、驗收檢核、禁區、壞範例，全部都在答第三個問題。

所以下次有人跟你介紹一個新框架，你只要問一句：它幫我答第三問了嗎？

成果展示：每人 2 分鐘，講通過率數字、消融實驗發現、下一個要沉澱什麼。

## 6. 工具鏈與工具矩陣

設計原則是教分類軸與算法，不教清單與數字。

具體平台名單與價格每期開課前更新，做成一頁附件，不進投影片主體。理由很現實：2025 熱門的平台名單已洗過一輪，價格一季就變，寫死等於教材半年報廢。

### 按「誰決定下一步」分類

| 類型 | 誰決定下一步 | 課程用途 | 適合的任務 |
|------|------------|---------|-----------|
| 對話型 | 你，每一步 | Block A、B 主力 | 單步、需要你判斷、變異大 |
| 協作型（cowork） | 你劃邊界，它在裡面跑 | Block C 結構化 | 有明確產出物、要來回修 |
| 自主型（E2E agent） | 它自己 | Block B 展示 | 步驟多、可驗證、錯了成本低 |
| AI IDE、檔案型 | 你，但它能讀寫檔案 | Block C 生成資料夾 | 產出是一組檔案而非一段話 |

### skill 資料夾的三種裝法（工具無關）

| 工具有什麼功能 | 怎麼裝 |
|--------------|-------|
| 有「專案 / Project」 | 檔案上傳知識庫，`SKILL.md` 貼進自訂指令 |
| 有「Skills / 技能」 | 整個資料夾直接放進去，最乾淨 |
| 什麼都沒有 | 保底做法：整包貼進對話開頭。累，但完全可用 |

你的資產是那個資料夾，不是那個工具。工具會倒、會改版、會漲價；資料夾是純文字，換到任何一家都能用。

## 9. 市場定位與差異化

### 市場缺口分析

| 現有市場 | 缺口 | 我們的定位 |
|---------|------|-----------|
| Prompt 框架課（STRIKE、CO-STAR 等） | 教措辭，而模型已經不缺措辭 | 教沉澱判斷，不教組裝句子 |
| AI 工具操作課 | 工具一改版就過期 | 產出是純文字資料夾，工具無關 |
| 企業 AI 培訓（顧問公司） | 講願景，沒有可驗證成效 | 帶走通過率數字與消融數據 |
| 免費 YouTube、模板包 | 別人的答案，不是你的判斷 | 從你自己的對話紀錄長出來 |

### 差異化優勢

這是目前唯一回答「半年後還能不能用」的課，Block D 的消融實驗有 Anthropic Claude Code 團隊的實踐背書。

產出可量化：通過率、消融分數，不是「學員很滿意」。

兩段式結構讓中間那一週的真實使用，把「第三次才沉澱」從口號變成課程結構。

教材經過實測，所有關於模型行為的敘述都跑過實驗，不押注在「模型會出錯」上。

### 與舊版 STRIKE 工作坊的對應關係

| 新課區塊 | 對應舊版 | 差異化重點 |
|---------|---------|-----------|
| Block A 認識這台機器 | 新增 | 舊版完全沒有模型素養 |
| Block B 提示詞作為設計 | 第一單元：戰法基礎 | STRIKE 保留但降為 15 分鐘鷹架，加上「證明它的天花板」 |
| Block C 收成資產 | 第五單元：武器庫 | 從「整理模板」升級為「從對話紀錄收成、驗收、考卷」 |
| Block D 汰換與消融 | 新增 | 舊版沒有任何汰換機制 |
| | 第二、三、四單元（資訊戰、數據戰、簡報戰） | 退場，改為學員自帶真實任務 |

### 必須退場的舊素材

舊版「壞 prompt 對 STRIKE prompt」的 20 組 A/B 對照表不可再上台。

實測顯示，那些「壞 prompt」在現在的模型上不會產生表格裡寫的爛答案。對照組已經垮了，上台會當場翻車，而且每上一次課就更嚴重一次。

替代做法是把對比改架在「規格模糊對規格明確，各跑 5 次」上。差異在變異度，不在單次品質，這根軸不會因模型變強而失效。

## 10. 教學設計原則

### 不押注在「模型會出錯」上

教材裡每一句關於模型行為的敘述都經過實測。在台上等它出錯，會等到一片沉默。可靠的是分歧不是錯誤：三份產出都對，但互相矛盾。

### 對比仍是最強的教學手段，但要換軸

| 對比軸 | 感官強度 | 保鮮 |
|--------|---------|------|
| 不給資料對給資料 | 高 | 永久 |
| 同一題問 3 次 | 高 | 永久 |
| low 對 high effort | 高 | 永久 |
| 規格模糊對明確（各跑 5 次） | 高 | 永久 |
| 有 skill 對沒 skill（消融） | 高 | 永久 |
| 壞措辭對好措辭（跑 1 次） | 已失效 | 已死 |

### 讓學員經歷「過去」，靠的是降低條件

學員沒有「以前 AI 很笨」的記憶，講古沒用。要現場製造摩擦：降 effort、抽掉資料、塞爆 context。把條件降下來，過去就在眼前。

### 收成優於創作

不要求學員「想出」驗收標準，那太難，多數會寫出「要專業」。讓他從自己的對話紀錄裡撿。對話已經替他做完外顯化，他只是還沒去收。

### 每個結論都由學員自己量出來

消融實驗的結果，就是全課論點的證明。老師不需要說服，數據會說。

## 12. FAQ

**我今天花時間做的 skill，模型一升級是不是就白費了？**

這是本課 Block D 專門回答的問題。答案要分兩類。你寫的「怎麼做」（指示）會被淘汰，Claude Code 團隊在 Opus 5 上線時就砍掉了自家 80% 的系統提示。但你寫的「怎麼算做好」（驗收標準、禁區、範例）不會，模型越強，它的能力越不是瓶頸，你的規格就越是唯一的瓶頸。課程會教你用消融測試自己量出哪一塊是哪一類。

**為什麼要分兩個半天？我只能來一天。**

中間那一週是課程的一部分，不是排程方便。本課的核心是「用過才知道漏了什麼」，一天課只能做到「第一次寫下來」。真的只能一天的話，我們有壓縮版（見收費模式），但 Block D 會砍掉，產出降級為草稿。

**這跟 Prompt 框架課有什麼不同？**

框架課教你把話講清楚。但現在的模型你話講得零零落落它也接得住，框架在補的洞，模型自己補上了。本課教的是模型補不上的那一格：你的驗收標準。課堂上會直接教 STRIKE，然後當場證明它的天花板在哪。

**我沒有技術背景，需要寫程式嗎？**

不需要。產出是一個純文字資料夾，全程複製貼上。

**需要付費訂閱 AI 工具嗎？**

不需要，免費方案可以完成全部實作。Block A 的成本實驗會教你怎麼估用量，反而幫你判斷該不該付費升級。

**公司禁用外部 AI 工具怎麼辦？**

課程刻意做成工具無關，你做出來的是資料夾，換工具只是換裝法。最陽春的對話框也有保底做法。

**我的工作涉及機密資料？**

全程用你自己脫敏後的素材，或用公版任務。課程會教「改掉，不要刪掉」的脫敏原則，結構要留著才有參考價值。

## 15. 風險識別與應對

### Day 2 缺席，或中間那週沒做作業

這是兩段式最大的結構性風險。作業沒做，Day 2 沒有原料。

應對：公版任務全套備妥，沒帶原料的人全程用它，不讓任何人空手。Day 1 結束前當場做完第一次，作業只是「再做兩次」。中間一週發一次提醒。Day 2 出席率列為正式 KPI，低於門檻就檢討 Day 1 的收尾。

### 模型太強，對比實驗失效

實測已證明「壞 prompt 得爛答案」不再成立，其他對比也可能隨模型變強而鈍化。

應對：每期開課前重跑 Block A 五個實驗，用當期數據上課。備妥「三份真實產出對照」實測檔，全班產出剛好很像時直接拿出來。教學語言統一為「三份都對，但三份不一樣」，不說「AI 出錯了」。

### 驗收檢核寫成「要專業」

這是全課最難的動作，也是最常見的失敗。

應對：助教必要，不是選配。提供對照範例（「要專業」改成「沒有出現口語詞」）。教三個引出技法。交棒測試會抓出漏網的，別人問不出來就代表沒寫清楚。

### 人數超載

超過 20 人又沒助教，Block C、D 不會有人做完。硬性上限 16 人配 1 講師加 1 助教，企業包班超過 16 人拆場次。

### 混部門班的交棒測試半殘

工程師判斷不了財務的產出對不對，且素材可能不能外流。同部門或同職能班效果最好，混班改為「只讀 skill 不做題，講出你會卡在哪」。

### 工具與價格資訊過期

平台名單一年洗一輪，價格一季就變。教分類軸與算法，名單與價格拆成每期更新的一頁附件，不進投影片主體。

### 企業資安顧慮

學員不能把真實素材放進 AI。公版任務全程可用，並教「改掉不要刪掉」的脫敏原則。

> 你上個月調出來的那個好用 Prompt，還在嗎？

## 附錄：理論依據

本課 Block D 的方法論來自 Claude Code 創造者 Boris Cherny 公開的實踐。

消融測試的做法是「刪掉整個 system prompt，再一行一行加回來，看每一行實際有什麼影響」。他建議的節奏是「每六個月，刪掉你的 CLAUDE.md、刪掉你的 skills、刪掉你的 hooks」。規模上，Claude Code 團隊在 Opus 5 上線時砍掉 80% 以上的系統提示，表現更好。加回的判準是只在看到模型重複跌倒的地方才加回。

他的第一守則是「給它一個驗證自己成果的方法，品質會變 2 到 3 倍」。而他點名的頭號反模式是過度規格化：該給的是 guardrails 與 exit criteria，不是 process。

exit criteria 就是本課的「成品照」。同一件事，工程語言與初學者語言的兩種說法。
