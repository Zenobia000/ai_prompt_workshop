## 2. 反常識型（轉發率最高）

視覺：純文字卡，「80%」做大

```
Claude Code 的創造者，在 Opus 5 上線那天砍掉了自家 80% 的系統提示。

模型表現反而更好。

他的建議是：每六個月，刪掉你的 CLAUDE.md、刪掉你的 skills、刪掉你的 hooks。
只在看到它重複跌倒的地方，才加回那一行。

⸻

聽起來像在說「別做了」。

但他同一場訪談裡的第一守則是這句：
「給它一個驗證自己成果的方法，品質會變 2 到 3 倍。」
「驗證，大概是大家最沒做對的那一件事。」

⸻

所以真正的訊息是：

會被模型升級淘汰的，是你寫的「怎麼做」。
留得住的，是你從來沒寫下來的「怎麼算做好」。

你存的那堆 Prompt 是前者。所以它們才會過期。
```

## 3. 痛點型

```
你上個月調出來的那個好用 Prompt，還在嗎？

⸻

你存的是措辭：怎麼開頭、要它扮演什麼角色、加哪幾句叮嚀。

但模型每強一次，這些就更接近廢話。

你沒寫下來的那些。怎樣算可以交出去、哪幾句話絕對不能出現、
上次被退回是因為什麼。

這些模型永遠猜不到，因為它們在你腦袋裡。
```

## 5. 短影音腳本（15–30 秒，9:16）

### A、消融實驗（最有畫面）

```
0-3s    畫面：一個 skill 資料夾
        字卡：這是我花兩小時做的

3-8s    刪掉「步驟」那一段，跑考卷，9/10
        字卡：刪掉「怎麼做」

8-14s   改成刪掉「驗收檢核」，跑考卷，4/10
        字卡：刪掉「怎麼算做好」

14-20s  字卡：你花時間寫的，模型不需要。
              你沒花時間寫的，才是在撐分數的那個。

20-25s  課程資訊，連結在 bio
```

### B、9/8/7

```
0-4s    三個視窗並排跑同一份逐字稿
4-10s   三份產出並排，數待辦：9、8、7
10-16s  圈出「購物車五月底上線」，只有一份有
16-22s  字卡：另外兩份看起來一樣完整。你不會發現。
22-25s  課程資訊
```
