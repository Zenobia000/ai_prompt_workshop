# 成熟度階梯 ＋ 工具安裝對照

---

## 一、你現在在第幾層

沉澱不是一步到位，是**爬階梯**。規則只有一條：

> ### 用不順的那一格，就是下一格要補的東西。

| 層 | 形態 | 什麼時候往上爬 | 成本 |
|---|---|---|---|
| **L0** | 每次重打 | —— | 每次都很痛 |
| **L1** | 存一段話在記事本 | 你打第二次的時候 | 1 分鐘 |
| **L2** | **挖空的填空卡** | 第三次，你發現有些地方每次都在換 | 15 分鐘 |
| **L3** | **一個資料夾**（＋檢核＋範例） | 你發現「光有話不夠，還要附那份參考檔」 | 1–2 小時 |
| **L4** | 自動觸發 | 你已經懶得想起來要用它 | 看工具 |

**這兩天做到 L3。** L4 不是今天的目標，而且很多人一輩子停在 L3 也完全夠用。

> 不要跳級。沒經過 L2 直接做 L3，你會挖錯洞 —— 因為你還沒看過它變過。

---

## 二、L3 的資料夾怎麼裝進工具

你做出來的是**一個資料夾**。工具只是裝它的地方，**換工具只是換裝法**。

### 通用原理

任何能做到這兩件事的工具都可以：

```
① 讀得到你上傳的檔案
② 記得住你的自訂指令（不用每次重貼）
```

### 裝法對照

| 工具類型 | 怎麼裝 | 資料夾對應到什麼 |
|---|---|---|
| **有「專案 / Project」功能的對話工具**<br>（Claude Projects、ChatGPT Projects 等） | 開一個專案 → 把資料夾裡的檔案全部上傳到專案知識庫 → 把 `SKILL.md` 的內容貼進「自訂指令」欄位 | 專案知識庫 ＝ 你的資料夾 |
| **有「自訂 GPT / 助理」功能的** | 建一個助理 → 上傳檔案 → `SKILL.md` 貼進 instructions | 知識檔案 ＝ 你的資料夾 |
| **有「Skills / 技能」功能的** | 直接把整個資料夾當 skill 放進去 | 一對一，最乾淨 |
| **開發者工具**（能讀本機檔案的） | 資料夾直接放進專案目錄 | 原生支援 |
| **什麼功能都沒有的陽春對話框** | **保底做法**：把 `SKILL.md` ＋ `驗收檢核.md` ＋ `禁區.md` 整包貼進對話開頭，範例貼在後面 | 每次重貼（累，但完全可用） |

> 各家工具的選單名稱、位置經常改版。上面寫的是**能力**不是**點擊路徑** ——
> 找不到入口的話，在你的工具裡搜尋「專案」「知識」「自訂指令」「instructions」。

## 三、裝完一定要測一次

**不要裝完就當作好了。** 跑一題，確認三件事：

- [ ] 它有**真的讀到**你的範例嗎？（問它：「你看到我給你的好範例了嗎？講一下它的格式」）
- [ ] 它有**照著檢核表**檢查嗎？（問它：「這份產出通過驗收檢核第幾條、沒過第幾條？」）
- [ ] 產出**跟好範例的形狀一樣**嗎？

第二點沒過的話，在 `SKILL.md` 的步驟最後一行明確寫：

```
最後一步：對 驗收檢核.md 逐條打勾，把結果列出來。沒過的不要交，回去改。
```

---

## 四、關於工具，一個提醒

不要花超過 20 分鐘在裝工具上。

> **你的資產是那個資料夾，不是那個工具。**
>
> 工具會倒、會改版、會漲價。資料夾不會 ——
> 它是純文字，換到任何一家都能用。

這也是為什麼今天做的是資料夾，不是「某某工具的設定檔」。

裝不起來完全不影響產出。**先用保底做法貼進對話跑起來，回去再研究安裝。**
