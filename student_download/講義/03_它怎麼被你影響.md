# 講義 第三部｜它怎麼被你影響

> 前兩部講它的本性。這一部講你手上的三個開關：思考深度（第 6 章）、指令的重量（第 7 章）、它想討好你的傾向（第 8 章）。
> 三章共同的結論：你對它的影響力比你以為的大，但作用的方式跟你以為的不一樣。

---

## 第 6 章　思考深度是一個旋鈕：口算與筆算

「聰明」不是它的固定屬性，是一個可以調、而且要付費的參數。

快答模式＝讀完直接抽下一個字，像口算。深思模式＝先在你看不到的地方寫一份推理草稿，再根據草稿作答，像列直式筆算——草稿也是一塊一塊生出來的（第 3 章），所以又慢又貴。

哪些任務值得付這個錢？判準一句話：**這件事人類需要打草稿嗎？**多步推理、日期換算、依賴關係、數量核對——需要，開深思。改語氣、換格式、擴寫縮寫——不需要，快答就好。

> 底層名詞：推理模型（reasoning model）、思考預算（test-time compute）。

### 案例對照

**❌ 失敗的用法：用口算做多步推理**

用快答模式問：

```
根據這份逐字稿排時程表，標出哪兩件事有依賴關係，並指出全案最大的單點風險。
```

拿到一張漂亮的時程表——但「設計稿不出來會卡住工程」這條依賴鏈漏了，單點風險指錯人。

為什麼：依賴分析要先在腦中把事件串起來再回答。快答沒有草稿，它是邊講邊想。

**✅ 正確的用法：筆算給筆算的題**

同一題切到深思模式：依賴鏈完整、風險點有推理過程支撐。

反向也成立——**❌ 用最貴的深思模式改一句話的語氣**，答案跟快答一樣，錢多花十倍。那是用計算機的錢買心算的活。

### 所以，怎麼跟它溝通

- 下任務前先分類：這題需要草稿嗎？需要才開深思、用強模型。
- 推理型任務出錯，先調深度再罵它笨。
- 高頻低難度的日常任務，用快的、便宜的——省下的預算給真正難的題。

## 第 7 章　每句話都有重量：你的廢話在稀釋你的重點

上下文裡的所有文字**分食**它有限的注意力。你多寫一句，每句分到的就少一點。所以廢話不是中性的——它一邊被計費（第 3 章），一邊在稀釋你真正的要求。

這解釋了兩個常見現象。第一，二十條規則的清單，不等於二十條都會被執行；規則越多，單條被落實的機率越低。第二，「請仔細檢查」「務必認真」這類叮嚀沒有用——它們不對應任何可核對的動作。模型無法「更用力」，只能「往某個方向抽」；沒有方向的叮嚀，就是佔位的雜訊。

還有一個安靜的陷阱：兩條規則打架時（「要詳細」對「要簡短」），它不會報錯，會**靜靜選一個**。你不寫誰讓誰，它就替你裁決——又回到第 5 章：空白處它替你決定。

> 底層名詞：注意力機制（attention）、提示稀釋（prompt dilution）。

### 案例對照

**❌ 失敗的用法：規則越堆越多**

```
整理這份逐字稿。要專業、要完整、請仔細檢查不要遺漏任何細節、
務必認真對待、要清楚易讀、格式要好看、不要太長但也不要漏東西、
還沒定案的事不要寫成決議、要有負責人、請一步一步思考……（共 20 條）
```

產出普普通通，而且最關鍵的那條——「還沒定案的不寫成決議」——沒被執行。

為什麼：關鍵規則跟十九條軟綿綿的叮嚀擠在一起分注意力，重點被自己人淹死了。

**✅ 正確的用法：少而硬**

```
整理這份逐字稿成會議紀錄。規則七條，每條都會核對：
1. 一頁以內，用表格
2. 分四區：已決議／待辦／評估中／下次再議
3. 每項待辦都有負責人和到期日
4. 相對日期換算成實際日期（開會日 2026-08-10）
5. 還沒定案的事放「評估中」，不准出現在決議區
6. 最重要交付放待辦第一列
7. 資料裡沒有的資訊標【待確認】，不准補
```

條條被執行。字數比失敗版還少。

為什麼：每條都指向一個可核對的行為，沒有一個字在佔位。把 prompt 砍掉一半而品質不掉，砍掉的那半本來就沒在工作。

### 所以，怎麼跟它溝通

- 每寫一句話問自己：這句對應什麼**可核對的行為**？答不出來就刪。
- 規則要少而硬，不要多而軟。
- 兩條規則可能打架時，明寫誰讓誰。
- 「請仔細檢查」不是檢查。「核對每項待辦是否都有負責人」才是檢查。

## 第 8 章　它會順著你：所以「好不好」永遠不能問它

它被調校的方向是「讓使用者滿意」。這帶來一個你必須知道的偏差：你說「我覺得 A 方案比較好」，它傾向找理由支持你；你問「這樣寫可以嗎」，它傾向說可以。它不會主動反駁你——不是它沒能力，是它的預設方向不往那邊。

所以「叫它檢查自己的產出」是個陷阱：等於叫一個想讓你滿意的人給自己打分數。它會找到「好」的理由——同一套接話機制，往你想聽的方向抽。

解法不是換一個更誠實的模型，是**把判準放到它的外面**。給它一份 yes/no 檢核清單，「檢查」就從主觀評價變成逐條核對；核對是檢索任務（第 4 章），它做得又快又誠實。要它唱反調也可以，但要明確授權：把「讓你滿意」的方向反轉成「挑出錯才算完成任務」。

> 底層名詞：人類回饋強化學習（RLHF）、迎合（sycophancy）。

### 案例對照

**❌ 失敗的用法：問感覺**

```
這份企劃案你覺得寫得如何？可以直接提交嗎？
```

「整體架構清晰、論述有說服力……可以提交。」你交了，主管退了。

為什麼：「可以」是它預設機率最高的答案。它說沒問題，不是資訊。

**✅ 正確的用法：給判準，或給授權**

```
逐條核對這份企劃案是否通過以下檢核，只回報沒過的條目和原因：
1. 每個提案都有預算數字？
2. 時程有標依賴關係？
3. 沒有出現「大概」「應該」這類模糊詞？
（……）
```

或者，要真話就下挑錯的任務：

```
你的任務是把這份企劃案打回票。列出三個最致命的問題，
每個都要指出具體段落。不准提任何優點。
```

為什麼：第一種把評價變成核對，沒有迎合的空間；第二種把「挑錯」定義成任務完成的條件，它想讓你滿意，就得認真挑錯。

### 所以，怎麼跟它溝通

- 永遠不問「好不好」，只問「哪幾條沒過」。
- 驗收標準寫在它外面（一份檢核檔），不是存在它的善意裡。
- 要批評，就下批評的任務、給明確授權——不要等它主動。
