# 講義 第一部｜它怎麼說話

> 讀這份講義不需要任何技術背景。每章都是同一個結構：先講清楚它是怎麼運作的，再給你一組「失敗的用法對正確的用法」，最後收成幾條你自己也推得出來的溝通原則。
> 案例是實測結果的整理示意，模型每一代行為會變，課堂上會用當期數據重跑給你看。

---

## 第 1 章　它是「接話機器」，不是「查資料機器」

模型只做一件事：讀完前面所有的文字，計算「下一個字最可能是什麼」，然後**抽**一個出來，再重複。它沒有在翻資料庫，沒有標準答案，也沒有「想好再說」。

「抽」這個字是關鍵。同一題問三次，三個答案，因為每次抽的路徑不一樣——這是設計，不是故障。所以「上次明明可以，這次又不行」不是你的錯覺，也不是它壞掉：上次真的可以，那是另一次抽樣。

反過來想，這也告訴你規格為什麼有用：你的要求寫得越明確，它「可以接的下一步」就越少，答案的變異就越小。規格不是禮貌，是把機率分布壓窄。

> 底層名詞：自迴歸生成、取樣（sampling）、temperature。想深挖再查，不用記。

### 案例對照

**❌ 失敗的用法：一句話交代，一次定案**

```
總結一下這場會議，列出待辦。
```

三個人用這句話跑同一份週會逐字稿，三份產出都漂亮——有負責人、有期限、排得整齊。但待辦數量是 9、8、7，最重要的那項交付有兩份漏掉，而且三份都把「請人去評估的方案」寫成了「決議」。

為什麼：範圍、格式、優先序你都沒說，它每次抽樣都替你重新決定一遍。三份都「對」，但互相不一樣。

**✅ 正確的用法：把可接受範圍寫窄**

```
把這份逐字稿整理成會議紀錄。驗收條件如下，全部符合才算完成：
1. 一頁以內，用表格不用長段落
2. 分三區：已決議／待辦／評估中（還沒定案的放這裡，不准寫成決議）
3. 每項待辦都有負責人和到期日
（……共六條）
```

同一份逐字稿跑五次，五份的形狀一致、關鍵交付都在第一列。

為什麼：六條驗收把「能接的下一步」壓到很窄，抽樣的自由度沒了，變異就沒了。

### 所以，怎麼跟它溝通

- 單次的好結果不算數，**變異度**才算數——重要任務先跑多次看穩不穩。
- 要穩定，就把可接受範圍寫窄。規格的本質是壓縮它的選擇空間。
- 它答得流暢是接話的本性，不是可信度訊號。

## 第 2 章　它有記憶上限，而且聊越久越健忘

它不記得你。每次回覆之前，它是把整段對話**從頭重讀一遍**——對話的連貫感是這樣造出來的假象。關掉視窗，一切歸零。

它一次能「看見」的內容有上限，像一張很大但有限的桌面。你貼的資料、你說過的話、它自己的回覆，全部占桌面。而且對話**中段**的資訊最容易被忽略：聊得越長，你早先說的每句話分到的注意力越稀。長對話越聊越歪，不是它累了，是你的重點被稀釋了。

> 底層名詞：上下文視窗（context window）、lost in the middle。

### 案例對照

**❌ 失敗的用法：把對話紀錄當雲端硬碟**

對話第 3 輪你說過「日期一律寫實際日期，不要『下週三』」。聊到第 30 輪，產出又冒出「下週三」。你罵它：「我不是說過了嗎？」

為什麼：那句設定沉在第 3 輪，前後被幾十輪內容包圍，權重被稀釋到接近雜訊。它沒有「忘記」——它是每次重讀時，越來越讀不到那句話。

**✅ 正確的用法：重貼，或重開**

發現它開始忘記設定的那一刻，二選一：把重要設定整段重貼一次（回到桌面最上層），或乾脆開新對話，開頭貼上整理好的規格與摘要。

為什麼：新對話＝乾淨的桌面，你的規格獨占注意力。這也是為什麼沉澱下來的規格檔（skill）每次貼在對話開頭，比「上次跟它講過」可靠一百倍。

### 所以，怎麼跟它溝通

- 一個任務開一個新對話；重要規格放開頭或結尾，不放中段。
- 要它記住的東西用「貼」的，不要用「聊」的。
- 它開始忘設定是正常現象，不是壞掉——重貼或重開，不要對罵。
- 重要成果自己存檔。對話紀錄不是雲端硬碟。

## 第 3 章　它看到的世界是「碎片」，不是你以為的字和圖

文字進到它眼裡之前，先被切成一塊一塊的碎片（token）——中文一個字約一到兩塊，英文一個常用詞約一塊。圖片更徹底：被壓縮翻譯成一組數字，它從來沒有「看見」原圖。

這解釋了兩件事。第一，帳怎麼算：費用＝進去的碎片＋出來的碎片，同樣內容中文比英文貴，你多寫的每句廢話都在雙向收費。第二，它為什麼數不好：「正好一百字」常失手、數不清圖裡有幾個人、看不清小字——它的量尺跟你的不一樣。這是結構性弱點，不是你提示詞寫得不好。

> 底層名詞：token、tokenization、視覺編碼。

### 案例對照

**❌ 失敗的用法：把精確計數交給它**

```
幫我寫一篇剛好 100 字的貼文。
```

出來 112 字。你說「重寫，要剛好 100 字」，出來 98 字。再來一次，105 字。同樣的：「這張團體照裡有幾個人？」——25 人的合照，它可能回 23。

為什麼：它看的是塊不是字、是壓縮向量不是照片。你在要求一個看電碼的人數原文字數。

**✅ 正確的用法：結構描述＋人工驗數**

```
寫一篇貼文：三句以內，80 到 120 字之間。
```

字數範圍它抓得住，精確值你自己數——花五秒。圖片同理：描述、分類、摘要交給它，「數量」自己點。

為什麼：把任務切開——「形」的部分（結構、長度區間、語氣）是它的強項，「精確計數」是它的結構性弱點，弱點處換人工。

### 所以，怎麼跟它溝通

- 格式要求用結構描述（幾句以內、一頁以內、用表格），不用精確字數。
- 精確計數類任務（剛好幾個字、數物件、逐字校對）**另設人工驗收**，不交給它自檢。
- 重複使用的長規格，沉澱成固定開頭——在成本上也划算（重複的部分可以被快取）。
