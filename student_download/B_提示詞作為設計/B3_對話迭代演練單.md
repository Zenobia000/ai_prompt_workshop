# B3　對話迭代演練單

Day 1 的真正產出不是一個好 prompt，是**一份對話紀錄**。

這份紀錄就是 Day 2 的原料。沒有它，明天你會坐在那裡憑空想「我的驗收標準是什麼」，然後寫出「要專業」「要完整」這種沒用的東西。

---

## 為什麼是對話紀錄

一次問到位是不可能的，也不需要。真實的用法是來回修。

而**每一次你說「不對，改成……」，都是你腦袋裡的標準當場被逼出來的那一刻**。

```
你打的字                        它其實是什麼
──────────────────────────────────────────
「太長了，壓到一頁」              → 長度標準
「把負責人加上去」                → 必要欄位
「不要用『相關同仁』這種寫法」      → 禁區
「參考我上次那份的格式」           → 參考成品
「這個是建議，不是決議」           → 領域規則
```

你不需要「想出」你的驗收標準。你只需要回頭把自己罵過 AI 的話撿起來。

**但前提是那些話有被留下來。** 這就是這份演練單的目的。

---

## 演練：跑一輪完整迭代

用你自己的任務。用你在 `B2` 的明確版 prompt 當起點。

### 規則

1. **不要一次寫到完美。** 先跑一版，看產出，再修。
2. **每次只改一件事。** 一次改五件，你不知道是哪一件起作用。
3. **修正要用完整的句子打出來**，不要只在腦袋裡想然後重寫 prompt。
4. **修到你願意直接交出去為止。**

### 記錄

| 第幾輪 | 我說了什麼修正 | 它改了什麼 |
|---|---|---|
| 1 | （初版，不算修正） | |
| 2 | | |
| 3 | | |
| 4 | | |
| 5 | | |

## 立刻做：把紀錄存下來

**現在就存，不要等回家。** 這是 Day 1 最重要的一個動作。

### 三種存法，挑一種

| 方法 | 怎麼做 | 適合 |
|---|---|---|
| **匯出對話** | 多數工具有匯出或分享連結功能 | 最完整，優先用這個 |
| **複製貼上** | 全選對話貼進一個 txt 或文件 | 通用，一定可行 |
| **截圖** | 從頭截到尾 | 最後手段，明天不好圈重點 |

### 存到哪裡

建一個資料夾，取名就用你的任務名稱：

```
我的任務名稱_對話紀錄/
├── 第1次_YYYYMMDD.txt
├── 第2次_YYYYMMDD.txt
└── 第3次_YYYYMMDD.txt
```

## 一週作業

接下來這一週，用今天摸出來的方式，把那件工作**實際做 2–3 次**。

### 為什麼是三次

| 第幾次 | 你在幹嘛 |
|---|---|
| 第一次 | 在做事。還不知道哪些會變 |
| 第二次 | 在確認不是偶然 |
| **第三次** | **這時候你才看得出哪些是真的不變** |

太早沉澱，會把「這次剛好這樣」寫成「永遠這樣」，之後每次用都要繞過它，用三次你就不用了。

今天算第一次。回去再做兩次就夠。

### 每一次都要做的

- [ ] 用你的 prompt 跑真實案例（不是練習，是你真的要交出去的東西）
- [ ] **每一句修正都打出來**，不要在腦袋裡改完直接重寫
- [ ] 存下完整對話紀錄
- [ ] 順手記一下：這次卡在哪？（見下方表格）

### 卡點紀錄

這張表明天很有用。每次做完花一分鐘填。

## Day 2 要帶的東西

- [ ] **2–3 份對話紀錄**（這是主餐，沒有它明天做不了）
- [ ] 2–3 份過去的成品，你自己認可的
- [ ] 如果有，一份**做壞的**——被退回的、你自己不滿意的

最後那份大家都不想帶，但它明天的價值比好的還高。**AI 只看好範例，不知道你嫌棄的是哪一種壞。**

---

## 沒做作業會怎樣

老實說：Day 2 你會用公版任務跑完全部流程，一樣學得到方法。

但你帶走的會是「用別人的任務練過一次」，不是「我自己的工作沉澱好了」。

差別在一個月後。**用自己任務做的人，那個 skill 還在用；用公版任務做的人，通常沒有。**

一週做兩次，每次多花不到十分鐘。這是這門課投資報酬率最高的十分鐘。
