# 把工作寫成食譜 — 填空卡

> 上一節你知道了「什麼值得寫」。這一節要把它**變成一張下次能直接用的卡**。

---

## 食譜的三個部分

一份工作沉澱下來，動作只有三個：

```
    每次都一樣的部分   →  寫死          （步驟）
    每次都在換的部分   →  挖空          （食材）
    做完長什麼樣       →  附上去        （成品照）
```

大部分人只做前兩個，然後很奇怪為什麼每次拿到的東西都不太一樣。

> **沒有成品照的食譜，做十次有十種樣子。**

---

## 但不要太早挖空

| 第幾次做 | 你在幹嘛 |
|---|---|
| 第一次 | 在做事。還不知道哪些會變 |
| 第二次 | 在確認不是偶然 |
| **第三次** | **這時候你才看得出哪些是真的不變** → 沉澱 |

太早挖空，會把「這次剛好這樣」寫成「永遠這樣」，
之後每次用都要繞過它，用三次你就不用了。

> ### 只挖你**真的看過它變過**的。沒看過它變，就先寫死。

---

## 演練：用素材 B 找出你的洞

### Step 1 — 不要改 prompt，直接跑素材 B

拿你在單元 02 寫好的 prompt，原封不動跑 `素材_會議逐字稿B.md`。

### Step 2 — 先看清楚：你的產出「不錯」

看一下。大概率它整齊、完整、看起來可以交。

**這正是問題所在。**

打開 `三份真實產出_對照.md` —— 那是三個人用三個不同的天真 prompt
跑同一份逐字稿的**實測結果**。三份都不爛，但三份不一樣，
而且**在同一件事上互相矛盾**。

### Step 3 — 找分歧，不是找錯誤

拿你的產出，跟那三份（以及隔壁同學的）比。
**不要問「誰對誰錯」，要問「哪裡需要有人拍板」。**

| 分歧點 | 三份真實產出怎麼分歧的 | 你的產出選了哪邊 |
|---|---|---|
| 推播技術債算**決議**還是**待決**？ | A 說決議，B、C 說待決 | |
| 「已完成」的事要不要列進決議？ | 只有 C 列了 | |
| 「本週五」「下週」要不要換成日期？ | 三份都只換了一部分 | |
| 逐字稿沒明說的事，可不可以補？ | A、C 都自己補了一個行動項 | |
| 負責人可不可以是「全體」？ | B 寫了「全體」 | |

### Step 4 — 每一個分歧點，都要你給一個答案

這才是重點：

> ### AI 沒有出錯。它每次都幫你做了一個決定 —— 而那個決定本來該是你做的。

| 分歧點 | 我們公司的答案 | 要寫進食譜的哪一格 |
|---|---|---|
| 已完成的事要不要列進決議 | 例：不列，另開「進度」段 | **成品照** |
| 相對日期要不要換算 | 例：一律換成 YYYY-MM-DD，換不出來的照抄 | **步驟** |
| 逐字稿沒說的可不可以補 | 例：一律不補，寫「未指定」 | **禁區** |
| 負責人可不可以是群體 | 例：不行，一定要具體人名或公司名 | **成品照** |
| | | |

> 這張表留著。下午做資料夾的時候，它們會直接變成**驗收檢核**的條目。
