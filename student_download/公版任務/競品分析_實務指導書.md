# 競品分析實務指導書：情報循環 × 真實數據 × 桌面 AI 執行

> 本指導書依據國際競爭情報實務（SCIP 情報循環、win-loss 與 battlecard 業界實證）編寫，
> 所有方法論與統計皆附來源。執行工具限定 **Claude Desktop** 與 **Codex Desktop** 的內建功能——
> 不寫程式、不用爬蟲，一般知識工作者就能照做。
> 課堂與練習一律使用**真實市場、真實數據**；本課的示範市場見《真實資料來源包》。

## 一、骨架：情報循環五步（SCIP）

競爭情報不是一次性的報告，是一個持續轉動的循環。國際競爭情報專業組織 SCIP 定義的五步：

```
① 規劃定向 → ② 蒐集 → ③ 處理分析 → ④ 交付 → ⑤ 回饋 → 回到 ①
```

每一步的實務要點與「桌面 AI 怎麼做」對照如下。

### ① 規劃定向（Planning & Direction）

**實務要點**：從「要支援的決策」出發，不是從「想知道的主題」出發。

- 壞的委託：「把競品 X 的所有資料給我」
- 好的委託：「競品 X 在中端市場降價，我們該不該跟？」

實務上這叫 KIT（Key Intelligence Topics）：先跟決策者確認本季要回答的 2–3 個問題，再開始蒐集。順序反了，就會做出五頁沒人讀的報告。

**桌面 AI 執行**：在 Claude Desktop 開一個 Project（或 Codex 開一個工作區），把本季 KIT、上一季報告、驗收檢核放進去——這就是你的「情報作戰室」，之後所有對話都在裡面進行，不用每次重新交代。

### ② 蒐集（Collection）

**實務要點**：來源有階層，每個數字都要帶戶籍（來源＋日期＋口徑）。

| 可信度 | 來源類型 | 例子 |
|---|---|---|
| 高 | 政府統計、財報、實地查證 | 監理掛牌數、上市公司財報、門市標價 |
| 中 | 產業媒體、第三方報告、平台評論 | 產業月報、電商銷量估算 |
| 低 | 新聞稿、官網文案、業配、社群風向 | 「會員突破 3 萬」「銷量第一」 |

低可信來源不是不能用——它是**信號**（對方想讓你相信什麼），不是**事實**。

**倫理紅線（SCIP 倫理守則）**：蒐集公開資訊合法且合乎職業倫理；假冒身分套話、入侵系統、取得非公開資料，不合法也不合倫理。這條線在 AI 時代更重要，因為越線變容易了。

**桌面 AI 執行**：
- Claude Desktop：開啟網頁搜尋直接查；深度研究（Research）模式跑「近半年主要競爭者動態」這類開放題
- Codex Desktop：內建瀏覽器逐站查證；**排程任務**（scheduled tasks）設成每月自動跑一次固定查詢——監測型情報最需要的就是這個
- 兩者皆可：把政府統計頁、財報 PDF 直接丟進對話讓 AI 抽數字，**要求先列引用原文再作答**

### ③ 處理分析（Processing & Analysis）

**實務要點**：把資料變成判斷。三個動作：

1. **查核**：交叉比對至少兩個來源；口徑不一（累計 vs 活躍、促銷價 vs 常態價）就並列呈現，不准自己挑一個
2. **信號解讀**：動作比文案誠實——徵才職缺、融資、通路上架、價格頁改版，各自指向什麼（見第三節信號表）
3. **So-what 三段式**：每條動態寫成【事實】→【影響】→【建議】，缺一段就不准上頁面

**桌面 AI 執行**：AI 最擅長②的整理和③的初稿，但**【影響】和【建議】的判斷是你的**——AI 不知道你的策略處境。讓它列選項與取捨，你來選。

### ④ 交付（Dissemination）

**實務要點**：產出要可行動（actionable），不是可歸檔（archival）。監測型的標準產出是**一頁動態報告**；業界的標準節奏是每週 30 分鐘掃描、每月 2–3 小時整理、每季半天深度回顧。

一頁報告的形狀：

```
標題列   本季競品動態｜報告日期｜資料截止日
第一句   執行摘要（本季最重要的一件事，一句話）
主體     最多三條動態，每條三段式
數字區   關鍵數字對照表，每格帶來源與日期
末行     下季要盯的兩個信號
```

**桌面 AI 執行**：把驗收檢核（yes/no 清單）做成 Skill 或放進 Project 指令，要求 AI 交付前先自查，任何一條不過先修再交。

### ⑤ 回饋（Feedback）

**實務要點**：報告交出去不是結束。決策者問了什麼、哪條建議被採納、哪個數字被質疑——這些回饋決定下一季的 KIT。被質疑的數字類型，寫進禁區；被追問的面向，加進檢核。

**桌面 AI 執行**：這就是本課的核心動作——把每一次被退、被問、被改的紀錄收成 skill 的更新。循環轉一圈，你的資料夾就厚一層。

## 二、為什麼值得做：業界實證

- 68% 的 B2B 交易至少面對一個直接競爭者，但銷售團隊的競爭應對自評只有 3.8／10 分（Crayon 州情報告）
- 持續經營 win-loss 分析的公司，63% 回報勝率提升；跑滿兩年以上的計畫，這個比例升到 84%（Clozd 2025）
- 使用 battlecard 的企業 71% 回報勝率改善（業界調查，見來源）
- 內部來源（員工見聞、通話紀錄）已是最大宗情報來源（54%），超過競品官網（48%）——你同事的見聞比對手的官網誠實（Crayon 2026）

最後一條對本課特別重要：**你自己的對話紀錄和團隊的第一手觀察，本身就是高價值情報源。**

## 三、信號解讀速查表

| 信號 | 讀法 | 去哪查（免費、公開） |
|---|---|---|
| 徵才職缺 | 徵冷鏈物流＝自建配送；徵電商營運＝要做 D2C | 104、LinkedIn Jobs |
| 融資／財報 | 拿錢後 6–12 個月必有大動作；毛利率變化透露定價策略 | 公開資訊觀測站（MOPS）、SEC EDGAR、新聞 |
| 通路上架 | 進量販＝走量與價格戰前兆；進專業通路＝走信任溢價 | 實地查證、通路 DM、電商平台 |
| 價格頁改版 | 方案變多＝測分層定價；門檻變低＝獲客成本壓力 | 官網（存檔對照用 Wayback Machine） |
| 政府統計 | 掛牌數、進出口、開店家數＝不會說謊的市占 | 政府資料開放平台、各部會統計處 |
| 評論與社群 | 客訴集中處＝對手的履約軟肋 | Google 評論、PTT、Mobile01、Dcard |

## 四、工具能力對照（本課的執行邊界）

| 步驟 | Claude Desktop | Codex Desktop |
|---|---|---|
| 定向：情報作戰室 | Projects（放 KIT、檢核、上季報告） | 工作區＋Memory（記住你的偏好與修正） |
| 蒐集：即時查證 | 網頁搜尋、Research 深度研究 | 內建瀏覽器逐站查 |
| 蒐集：定期監測 | 手動每月跑（存成固定提示詞） | **排程任務**每月自動跑 |
| 分析：讀檔抽數字 | 上傳 PDF／截圖，要求列引用 | 同左 |
| 交付：一頁報告 | Artifacts 產出、Skills 裝檢核 | 檔案輸出 |
| 回饋：沉澱 | Skills 資料夾（本課產出物） | AGENTS.md／自訂指令 |

兩個工具都能走完全程。差異：Claude 的 Skills 與本課產出物格式一致；Codex 的排程任務最適合監測型的固定節奏。課堂用其一即可，方法不變。

## 五、常見死法（驗收檢核就是它們的反面）

1. **Feature dump**：規格大表沒有一條 so-what
2. **話術當事實**：新聞稿數字直接進報告
3. **沒有日期的數字**：三個月前的促銷價當現價
4. **只看產品不看動作**：漏掉徵才、融資、通路信號
5. **建議欄只有「持續觀察」**：等於沒有建議
6. **五頁**：經營會議沒人翻到第二頁
7. **AI 時代新增——沒開搜尋就問市況**：模型的知識有截止日，問上個月的掛牌數而不開搜尋、不餵資料，得到的是一本正經的編造
