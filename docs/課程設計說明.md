# 課程設計說明（講師用）

> 這份不是講義，是**設計理由書**。
> 你照著 `講師手冊.md` 就能上課，但如果現場要即興、要回答學員的刁鑽問題，
> 你得知道每一段為什麼長這樣。

---

## 一、為什麼要改掉舊版

### 舊版的致命問題：對照組垮了

舊教材（`archive/strike_舊教材/`）的核心演練是 **A/B 對照**：

```
壞 prompt「幫我寫信給主管說報告要延期」→ 爛回覆
好 prompt（STRIKE 六要素）             → 好回覆
```

這在 2023 年成立。**現在不成立了。**

你把那句「壞 prompt」丟給現在的模型，它會給你一封像樣的信，甚至反問你原因。
對照組垮掉 → 學員看不到差別 → 整個單元的說服力歸零。

而且這件事**會在台上發生**，不是理論風險。

### 更根本的問題：框架教的是「措辭」

STRIKE / CTCO / CO-STAR 這類框架，本質上是在教學員**把話講得完整**。
但模型變強的方向，正好就是「你話講得不完整我也接得住」。

**框架在補的那個缺口，模型自己補上了。**

所以繼續教框架，等於教一個每半年貶值一次的技能。

### 但有一格模型永遠補不上

三問裡的第三問：**怎麼算做好了？**

這不是能力問題，是**資訊問題** —— 你的驗收標準在你腦袋裡，模型拿不到。
再強的模型也猜不到你們公司的會議紀錄一定要有負責人跟日期。

**新課程把整堂課壓在這一格上。**

## 二、新舊對照

| | 舊版 | 新版 |
|---|---|---|
| 教什麼 | 六要素怎麼填 | 什麼值得寫下來 |
| 演練 | 壞 prompt vs 好 prompt | 沉澱前 vs 沉澱後，跑同一份考卷 |
| 產出 | 一疊模板 | **一個驗證過的 skill 資料夾** |
| 對照方式 | 單次比好看 | **10 次比通過率** |
| 會不會過期 | 模型一強就過期 | 模型越強越好用 |

> 注意第四列：**新版的對照方式本身就在示範課程教的原則。**
> 「單次對照不算數，差異在分布上」—— 這句話同時是教學內容也是教學方法。

## 三、三個核心設計決定

### 決定一：全程只用一個範例

初學者最常在「每一段換一個例子」的課裡迷路。
所以單元 01–06 **從頭到尾只有一個範例**：

```
會議逐字稿  →  行動項清單
```

選它的理由：

- **人人都做過**，不需要任何領域知識
- **產出的好壞看得見** —— 一份會議紀錄有沒有用，不用專業知識就能判斷
- **它的驗收標準不是常識，但講出來就懂** —— 這是教第三問最理想的載體

> ⚠️ **不要用「摘要 vs 行動項」當賣點。** 第一版的設計說明寫「初學者會打
> 『幫我摘要這個會議』，拿到一份沒用的摘要」—— **實測推翻了這個假設**：
> 連「總結一下這場會議」都會產出七項含負責人與期限的待辦表。
>
> 真正可靠的落差在別處：**三份產出的待辦數量是 9 / 8 / 7，
> 而「購物車五月底上線」這個最重要的 Q2 交付，三份有兩份沒列進去。**
> 完整實測見 `student_download/02_值得寫下來的五類/三份真實產出_對照.md`。

同時，學員用**自己帶來的任務**平行做一份。範例是拐杖，自己的任務才是成品。

### 決定二：第二份逐字稿製造「分歧」，不是製造「錯誤」

單元 03 要教「哪些是不變的、哪些是會變的」。
如果第二份素材跟第一份太像，**學員什麼都發現不了**，這段就白教。

所以 `逐字稿B` 刻意加了三個第一份沒有的狀況：決議被推翻、負責人是外部廠商、
討論但沒有結論。

#### ⚠️ 但這三個「陷阱」不會讓模型出錯 —— 已實測

**2026-08 實測**（三個天真 prompt × 逐字稿 B，各自獨立跑）：

| 原設計的陷阱 | 實際觸發 |
|---|---|
| 決議被推翻 → 新舊並存 | **0/3** 三份都正確標註「該決定已取消」 |
| 外部廠商負責人 → 填不出來 | **0/3** 三份都正確寫出「Eric（外部工作室）」 |
| 無結論 → 被寫成決議 | **1/3** 只有一份自相矛盾 |

用最天真的 prompt（「幫我把這份逐字稿整理成會議紀錄」）跑出來的東西，
品質跟教材裡手寫的好範例不相上下。

> **這是本教材第一版的設計錯誤，已修正。**
> 押注在「模型會出錯」，跟舊版 STRIKE 的 A/B 演練是同一個賭注 ——
> 而那個賭注就是舊版垮掉的原因。同一個坑不要踩兩次。

#### 改成押注在「分歧」上

同一份實測資料裡，**這些是 100% 可重現的**：

| 觀察 | 重現率 |
|---|---|
| 三份產出的**形狀完全不同**（4 段 / 敘事式 / 3 段＋備註） | 100% |
| **同一件事被歸到不同類別**：推播技術債，A 列「決議」、B/C 列「待決」 | 100% |
| 相對日期（「下週」「下個月月會前」）沒有全部換算 | 100% |
| 逐字稿沒說的事被自己補上（「Q3 規劃」行動項） | 2/3 |

於是單元 03 的那句話從

```
❌ 「你看，AI 出錯了 → 所以要沉澱」
```

改成

```
✅ 「三份都對，但三份不一樣 → 所以要沉澱」
```

**後者更強，而且它不需要模型變笨。** 模型越強，「三份都對但互相矛盾」的說服力越高 ——
因為學員沒辦法用「換個更好的模型就解決了」來迴避。

實測資料本身已經做成教材：`student_download/03_寫成食譜/三份真實產出_對照.md`。
**全班產出剛好很像的時候，直接拿那份出來用** —— 那是這份檔案存在的理由。

#### 這條線不要拆

學員在單元 03 找到分歧點 → 單元 04 寫成檢核條目 → 單元 05 變成考卷題目。
**一條線串到底，這是整份教材最精密的地方。**

### 決定三：不用「函式」「參數」這種詞

心法④的原型是工程概念（抽函式：固定的寫死、變動的變參數、定義回傳值）。
對工程師講「抽函式」三個字就懂，對初學者講會直接放棄。

所以全程用 **食譜** 這個比喻：

| 工程說法 | 課堂說法 |
|---|---|
| 固定邏輯 | 步驟 |
| 參數 | 食材（每次換） |
| 回傳值型別 | **成品照**（做好長什麼樣） |
| 單元測試 | 考卷 |

比喻要一致到底，不要中途混用。**「成品照」這個詞特別重要** ——
它讓「驗收標準」從一個抽象名詞變成一個學員能想像的東西。

## 四、每個單元要打中什麼

| 單元 | 表面在做 | 真正要打中的 |
|---|---|---|
| 01 | 砍字實驗 | **鬆一口氣** —— 你不用背框架。同時破除「prompt 要寫很長」的迷信 |
| 02 | 三人同素材比對 | **撞牆** —— 三個人拿到三份不同的東西，問題不在 AI |
| 03 | 兩份輸入挖空 | **看見結構** —— 原來我的工作是有形狀的 |
| 04 | 做資料夾 | **手上有東西** —— 從抽象變成一個可以拖曳的實體 |
| 05 | 跑考卷 + 交棒 | **證據** —— 第一次能講出數字，不是「感覺比較好」 |
| 06 | 標記保存期限 | **可持續** —— 這套東西一年後還活著 |

單元 01 和 02 的情緒設計是刻意的：**先鬆一口氣，再撞一次牆。**
先鬆是因為初學者對 prompt 課有「又要背東西」的預期，要先拆掉。
再撞是因為沒撞過牆的人，不會覺得驗收標準重要。

## 五、跟 M0–M9 工程課的關係

`archive/M0-M9_懶人包.md` 是另一門課（**怎麼做出一套可控的 AI 系統**）。
兩門課承重的重疊只有四塊，但那四塊是這門課的地基：

| M0–M9 的 | 在這門課的哪裡 |
|---|---|
| M2「刪掉 Model Rule、只留 Business Rule」 | **心法⑦** 保鮮規則，單元 06 |
| M2「廢話是模型必須服從的雜訊」 | **心法②** 砍字實驗，單元 01 |
| M7「二元判準、同一份 dataset 比對」 | **心法⑥** 十題考卷，單元 05 |
| M9「他會來問你＝你的判斷還沒收斂」 | **心法⑥** 交棒測試，單元 05 |

M0–M9 的 M4（RAG）、M6（多 agent）、M8（provider 抽象）在這門課用不到。
**如果學員問起，明確告訴他那是另一門課，不要硬扯。**

## 六、可裁切的版本

| 場次長度 | 上哪些 | 產出降級成 |
|---|---|---|
| **一天（6h）** | 00–06 全上 | 完整 skill ＋ 通過率 ＋ 交棒過 |
| **半天（3h）** | 00, 01, 02, 03, 04（輕） | 一張填空卡 ＋ 資料夾骨架 |
| **2 小時體驗** | 01, 02 ＋ 展示做好的範例 skill | 一份雜訊清單 ＋ 五類盤點表 |

**不可以砍的是單元 05。** 砍掉它，這門課就退化成「大家一起寫模板」的手工藝課。
時間不夠寧可砍單元 06，也要留 05 的考卷演練 —— 哪怕只跑 3 題。
