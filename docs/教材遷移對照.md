# 教材遷移對照

這門課的教材經過三代。這張表說明每一份的去向與理由。

開課前掃一遍，你就知道哪些還能拿來用、哪些不要再拿出來。

```
第一代  STRIKE 提示詞戰法（七字訣 ＋ 三層進攻 ＋ 資訊戰/數據戰/簡報戰）
   ↓    對照組垮了
第二代  沉澱工作坊（七單元：00 課前 → 06 不要讓資產爛掉）
   ↓    缺模型素養與汰換機制
第三代  A/B/C/D 四區塊（現行）
```

舊教材沒有刪除，全部在 `archive/`。

## 二、第一代到第三代（STRIKE 舊教材）

### 最重要的一份：不可再上台

`archive/strike_舊教材/prompt_sample/Prompt_sampleUnit01.md`

那 20 組「壞 prompt → 爛回覆 / STRIKE prompt → 好回覆」的 A/B 對照表。

**不要再上這個單元。理由不是它做得不好，是對照組垮了。**

你把表格裡的「壞 prompt」（例如`幫我寫信給主管說報告要延期`）丟給現在的模型，它不會回那句敷衍的話，它會給你一封像樣的信，甚至反問你原因。

```
台上會發生的事：
  講師：「大家看，壞 prompt 就會得到這種爛答案」
  學員：「可是我這邊跑出來的還不錯耶」
  → 對照組垮掉 → 整個單元的說服力歸零
```

而且這**每上一次課就更嚴重一次**。

替代做法見 `student_download/B_提示詞作為設計/B2_規格對照_五次實驗.md`：不比單次好不好看，比五次的變異度。這根軸不會因模型變強而失效。

## 四、架構層面的改動

| 第一代 | 第三代 | 理由 |
|---|---|---|
| `assets/` 與 `student_download/` 內容重複 | 只留 `student_download/` 一份 | 同一份東西存兩處，改一邊忘一邊 |
| 沒有講師端文件 | `docs/` 四份 | 教學設計只存在講師腦袋裡，換人帶不了 |
| 檔名 `D1` `P3` 這種編號 | 區塊代號加中文任務名 | `D6_personal_arsenal_template.md` 學員看不出那是什麼 |
| 素材散在各單元 | `公版任務/` 共用區 | 新結構下素材跨區塊共用 |
| 沒有每期維護機制 | `docs/開課前檢查清單.md` | 這門課有五項每期都要重跑 |

最後一項是第三代才有的。**這門課教「你的資產會過期，要定期重測」，教材自己當然也適用。**
